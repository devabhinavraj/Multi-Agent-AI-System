## What is Multi-Agentic AI System?

Researching a topic manually often requires searching multiple sources, opening webpages, reading their content, collecting useful information, and finally organizing everything into a structured report.

**Multi-Agentic AI System** automates this research workflow using multiple specialized AI agents.

The system accepts a research topic such as:

```text
What is the impact of AI in Software Development in 2026?
```

The research process is divided into multiple stages:

1. **Search** — the Search Agent searches the web and identifies relevant sources.
2. **Read** — the Reader Agent scrapes the URLs returned by the Search Agent.
3. **Report** — the collected information is used to generate a research report.
4. **Critic** — the generated report is reviewed for quality and completeness.

Unlike a fully autonomous system, this project keeps the **human in the loop**. Before an agent executes an external tool, the user is asked for approval.

## 🤖 Agents

The system currently contains two primary agents.

### 🔎 Search Agent

```python
build_search_agent()
```

The Search Agent is responsible for finding relevant sources for the user's research topic.

It uses Tavily to search the web and returns information including:

* **Title**
* **URL**
* **Context**

The returned URLs are then passed to the Reader Agent.

---

### 📖 Reader Agent

```python
build_reader_agent()
```

The Reader Agent receives the URLs generated by the Search Agent.

It uses **BeautifulSoup** to scrape and extract readable webpage content.

The extracted content becomes the research context used for generating the final report.

## 🛡️ Human-in-the-Loop

A major component of this system is the **human approval guardrail**.

Agents are not allowed to execute external tools automatically.

Before every tool call, the system asks the user:

```text
Agent wants to call 'tool_name'. Approve? (yes/no):
```

The user can:

```text
yes
```

to allow execution, or:

```text
no
```

to deny the execution.

### `wrap_tool_call`

The approval mechanism is implemented through a tool-call wrapper:

```python
def human_approval(request, handler):
    """Ask for human approval before every tool call."""

    try:
        tool_name = request.tool_call["name"]

        confirm = input(
            f"Agent wants to call '{tool_name}'. Approve? (yes/no): "
        )

        if confirm.lower() == "no":
            return ToolMessage(
                content="Tool call denied by user.",
                tool_call_id=request.tool_call["id"]
            )

        return handler(request)

    except Exception as e:
        return ToolMessage(
            content=f"Tool execution failed: {str(e)}",
            tool_call_id=request.tool_call["id"]
        )
```

This creates the following execution boundary:

```text
Agent
  │
  ▼
Tool Call
  │
  ▼
Human Approval
  │
  ├───────────────┐
  │               │
 YES              NO
  │               │
  ▼               ▼
Execute         Deny
Tool            Tool Call
```

This gives the user control over when an agent can interact with external tools.

## Detailed Usage Guide

</summary>

<br>

### 🔎 Step 1: Research the User Query

The system first accepts a research topic from the user.

Example:

```text
Enter a Research Topic:
What is the impact of AI in Software Development in 2026?
```

The topic is passed to the Search Agent.

```text
User Query
     │
     ▼
Search Agent
```

---

### 🔐 Step 2: Approve the Search Tool

Before the Search Agent executes Tavily, the human approval middleware intercepts the tool call.

```text
Agent wants to call 'tavily_search'.
Approve? (yes/no):
```

If the user enters:

```text
yes
```

the tool is executed.

If the user enters:

```text
no
```

the tool call is denied.

---

### 🌐 Step 3: Search the Web

The Search Agent uses Tavily to search for relevant information.

```text
Research Topic
      │
      ▼
    Tavily
      │
      ▼
Relevant Sources
      │
      ├── Title
      ├── URL
      └── Context
```

The resulting source information is passed to the next stage.

---

### 📖 Step 4: Read the Sources

The Reader Agent receives the URLs returned from the Search Agent.

```text
Search Results
      │
      ▼
Reader Agent
      │
      ▼
Web URLs
```

The Reader Agent then uses BeautifulSoup to extract webpage content.

```python
BeautifulSoup
      │
      ▼
HTML Parsing
      │
      ▼
Readable Content
```

---

### 🔐 Step 5: Approve the Scraping Tool

Just like the search operation, the user must approve the tool execution before the Reader Agent accesses the webpage.

```text
Agent wants to call 'web_scraper'.
Approve? (yes/no):
```

The user maintains control over the external request.

---

### 📝 Step 6: Generate the Research Report

After the webpage content has been extracted, the collected information is passed to the report generation stage.

```text
Extracted Web Content
          │
          ▼
   Research Context
          │
          ▼
    Report Generation
          │
          ▼
   Structured Report
```

---

### 🔍 Step 7: Critical Review

The generated report is then reviewed critically.

The review stage focuses on identifying:

* Missing information
* Weak explanations
* Unsupported claims
* Inconsistencies
* Incomplete coverage

```text
Research Report
       │
       ▼
 Critical Review
       │
       ▼
Final Research Output
```
